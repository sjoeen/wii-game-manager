# Deployment — `sjoeen/wii-game-manager`

Target project site: **https://sjoeen.github.io/wii-game-manager/**.

## Static, already-built publishing

The repository root contains an already-built, self-contained `index.html`. It embeds the interface, styles, application code and JSZip. There are no runtime CDN/module/asset-base requirements. `.nojekyll` requests plain static publishing; no Jekyll project or custom domain is configured.

Upload/commit the files **inside** the supplied `wii-game-manager` folder to the root of the repository. Preserve `.nojekyll`, `.github`, source, docs and tests. Do not publish your personal SD card or games; those are selected on the local device only after opening the website.

In **Settings → Pages** select **Deploy from a branch**, branch **main**, folder **/(root)**. Save and wait for the Pages deployment to complete. The included workflow is checks only; it intentionally does not request Pages write permissions or deploy the site.

GitHub documents branch-based publishing and project-site addresses here:
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages

## Using Git

For an existing repository, clone it, copy the package contents into it without replacing its `.git` directory, inspect the diff, then commit and push:

```sh
git clone https://github.com/sjoeen/wii-game-manager.git
cd wii-game-manager
# Copy the CONTENTS of the extracted package into this directory.
git status
npm run verify
git add .
git diff --cached --stat
git commit -m "Add streamed folder mode and reviewed disk changes"
git push origin main
```

`npm run verify` requires Node 22+ but has no npm dependencies to install. The code is already built, so a browser/GitHub Desktop upload also works. Do not force-push over unrelated history. If GitHub asks for authentication, use your normal GitHub login/credential manager; the website itself needs no token.

## Updating source later

Edit `template.html`, `styles.css`, the JS modules or upload specs. Run `npm run build`, then `npm run verify`. Commit generated `index.html`, `Wii-SD-Manager.html`, `dev.html` and `UPLOAD-GUIDE.md` together with source. `check:build` intentionally fails on stale generated bytes.

`package.json` and the lockfile both identify `wii-game-manager` and the project URL. If you change the repository name again, update those metadata fields, this documentation, the `start:pages` command and the home link in `404.html`.

## HTTPS and direct folder permissions

Use the top-level HTTPS site. Browser directory access requires supported APIs, a trustworthy context and a user action. Read permission is requested by **Open SD / USB**. Write permission is requested by the explicit final **Apply to selected folder** button. A website cannot automatically grant itself these permissions.

Direct folder mode does not work in every browser or embedded preview. Use current desktop Chrome/Edge for your first test. When the site says access is unavailable, follow its explanation instead of renaming files or increasing ZIP limits. A rejected protected drive root may be usable via a normal computer backup folder; do not work around browser security policies.

References:
- https://developer.chrome.com/docs/capabilities/web-apis/file-system-access
- https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker

## Local server and project-path checks

```sh
npm run start:pages
# http://127.0.0.1:8080/wii-game-manager/
```

The development server binds locally, only serves files and has no upload endpoint. `npm run start` serves the same files at `/`. Port can be changed with `-- --port 8765`. `dev.html` loads relative source modules; `index.html` stays self-contained. The root of the local project mount redirects a missing trailing slash correctly, and the custom 404 links to `/wii-game-manager/`.

The Node tests serve and fetch actual HTTP bytes under both `/` and `/wii-game-manager/`. The release environment blocked Chromium navigation to localhost/file URLs with `ERR_BLOCKED_BY_ADMINISTRATOR`, so those native launch checks are recorded as **blocked**, not passed. No browser policy was changed. Browser interactions were tested separately by loading the compiled bytes into a test document. See the release report.

## Troubleshooting

**404:** confirm `index.html` is at repository root, the correct branch/root is selected, and deployment has finished. Check the repository spelling in the address. The app does not belong at the account root URL unless you separately configure an account site.

**Old screen after an update:** verify the footer says v3.0.0 and the first channel says Open SD / USB. Reload the page after the deployment completes; a hard refresh may be needed. Never replace the website files on the physical Wii card.

**No folder picker:** open the published HTTPS page directly in a supported browser. A private session, mobile picker, protected location, managed browser or iframe can deny it. ZIP fallback has its own small-archive limits, not a hidden large-library mode.

**Permission revoked/disconnected drive:** reconnect and reopen/refresh; review any recovery operation before editing. Do not delete manager journals blindly.

**Red checks:** read the failing check. A stale build is corrected with `npm run build`; configuration does not authorize modifying game files. Checks and Pages publishing are separate workflows.

**Renaming a repo:** GitHub repository redirects do not guarantee that all Pages URLs/paths remain correct. Update the package path metadata and 404 link too, then inspect Pages settings.
